# 离散保证金与清算窗口：为什么 10% 的冲击会直接落到 18%

**上一篇我关上了"内生危险"的闭环，并留下两条更犀利的读者评论：强制卖出不是连续的 ODE；而把美联储救市当成残差的风险模型，永远漏掉"强制卖出流持续了多久"这个变量。这篇就是这两条评论催生的模块——V9-P3 `discrete_margin.py`。同样的冲击、同样的账户，一个模型给出斜坡，另一个给出台阶。**

---

## 我一直悄悄带着的假设

我的系统动力学模块（第四篇）把强制卖出建模成**连续流**：每一步都盯市，卖压是账户低于阈值程度的平滑函数。数学上是 ODE，输出是一条斜坡——一场"滑下去"的崩盘。

一个做衍生品的人一眼能看到这个假设的三个问题：

1. **保证金不是连续盯市的。** 券商按间隔检查账户——每天，或按约定的盯市点。两次盯市之间，就算价格已经跌破阈值，也什么都没发生。
2. **阈值不是分散的。** 它们落在整数位上——10%、15%、20%——而且大量账户共享同一个阈值。价格跌破 15% 时，*所有*卡在 15% 的账户在同一批里同时触发。
3. **批次会推动价格穿过盘口。** 强制卖出砸进一个很薄的订单簿，价格跳空，而跳空本身又越过下一个整数位——下一批账户正在那里等着。

这就是为什么正如评论所说：_"一个 10% 的冲击可以跳过 12%，直接落到 18%，而任何人都来不及补充保证金。"_ ODE 假设恰好抹平了让崩盘呈现台阶状的机制。

## 模块的三个部件

`discrete_margin.py` 把每一条都显式化：

| 机制             | 实现                                                                           |
| ---------------- | ------------------------------------------------------------------------------ |
| **离散盯市**     | 每 `mark_interval = 3` 步检查一次保证金，而非每步                              |
| **整数阈值聚集** | 账户集中在整数位：-10%（25% 账户）、-15%（30%）、-20%（25%）、-25%（20%）      |
| **批量清算**     | 价格穿越共享阈值时，整个桶一次性清算；跳空可以在**同一个盯市轮内**穿越下一阈值 |
| **清算窗口**     | 从首次到末次清算的步数 + 累计强制卖出流——VaR 永远不定价的部分                  |

对照组是旧的 ODE 式释放：同样的阈值、同样的账户，只是卖压按缺口比例平滑释放。一次模拟，两种形状。

## 同样的冲击，两个模型各自的表现

对两者施加一个 -15% 的外生冲击：

```
第 3 步（离散版第一次盯市）：
  价格 0.856 ≤ 0.90  → -10% 桶（25%）清算  → 价格 0.824
  价格 0.824 ≤ 0.85  → -15% 桶（30%）清算  → 价格 0.787
  价格 0.787 ≤ 0.80  → -20% 桶（25%）清算  → 价格 0.757
  （同一个盯市轮内连穿三档，来不及补充保证金）
第 6 步（下一次盯市）：残余卖压把 -25% 桶也拖下水
```

| 指标                            | 离散（聚集）         | ODE（平滑）  |
| ------------------------------- | -------------------- | ------------ |
| 最大回撤                        | **-29.6%**           | -15.4%       |
| 单步最大跌幅                    | **0.121**            | 0.004        |
| 损失集中度（单步跳空 / 总跌幅） | **0.409**            | 0.024        |
| 清算事件                        | 4 个批次             | 1 条平滑斜坡 |
| 清算窗口                        | 3 步，累计流量 0.846 | —            |

用评论者的框架读这张表：**在 ODE 世界里只滑到 -15% 的同一个冲击，在离散世界里一个盯市轮内连穿三档，在任何人来得及反应之前就落在 -24% 附近**，残余卖压再拖垮最后一个桶，最终 -29.6%。尾部不只是更深——它是**台阶形的**。ODE 假设不是保守，而是从结构上对坏结果的形状失明。

## 清算窗口——VaR 漏掉的部分

第二条评论切得更深：一个给美联储的*反应*定价、却不给美联储的*缺席*定价的风险模型——或者说，把央行干预当成未建模残差的模型——定价的是冲击，不是过程。

窗口有两个可度量的部分：

- **持续时间**：首次与末次强制清算之间的步数（这里是 3）
- **流量**：窗口开启期间流经市场的累计卖出（这里是 0.846 个账面）

让它可度量的意义在于：**2020 年不是"美联储修好了新闻"。** 是美联储缩短了窗口——通过各类工具和做市支持吸收强制卖出的*流*，让卖盘在到达下一个阈值之前停止自我强化。切断流量，楼梯就不再是楼梯。

模块把这一点做成一个可选的 backstop：从某个触发步开始，每步吸收固定量的卖出——2020 式，_切流量，不切新闻_：

| 指标                 | 无干预 | Backstop（吸收流量） |
| -------------------- | ------ | -------------------- |
| 最大回撤             | -29.6% | **-28.3%**           |
| 累计强制卖出流       | 0.846  | **0.648（−23%）**    |
| 终期价格（第 40 步） | 0.847  | **0.858**            |

切流量阻止不了第一次跳空——没人能在盯市轮内补充保证金。但它缩短了尾部：流经市场的卖盘变少，-25% 桶不再被残余卖压拖下水，恢复更快。这就是用一张表讲完的整个 2020 故事：你挡不住第一个批次，但你能挡住*级联*。

## 诚实的边界

- **这是机制模型，不是校准。** 参数（盯市间隔、桶占比、流量冲击、backstop 时点）都有文档、可配置，是为了展示结构而选取——不是对任何单次崩盘的拟合。声称的是反馈的*形状*，不是下一次回撤的点估计。
- **"跳过"是结构性的，不是预测。** 模块说的是：_给定离散盯市和整数阈值，批量清算会在一个盯市轮内跳穿多个档位。_ 它不声称下一次崩盘恰好落在 18% 或 24%。
- **窗口指标才是交付物。** 诚实的贡献是让"强制卖出流持续多久"成为一个风险报告能携带的数字，而不是一个残差。

机制模型的价值在于告诉你*什么样的结构能产生这个尾部，下一步该去度量什么*。下一步要度量的，是真实保证金账本里清算窗口的实际时长——和 GEX 一样，恰好是那些不免费的数据。
